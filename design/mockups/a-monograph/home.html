§2

How I work

I start with what must never go wrong. In a payments system it’s money counted twice; in a hospital it’s one patient’s record shown to the wrong person. Then I design so that mistake can’t happen quietly. It either can’t happen at all, or it fails loudly in a test.11In FloatBook nothing is edited in place. Mistakes are voided or reversed, and both sides stay in the ledger.

Money is stored as whole kobo, never as decimals. Every record says where it came from. Every README says what doesn’t work yet.22FloatBook’s README opens with an “honest note”: it doesn’t connect to Moniepoint, OPay or Palmpay yet.
